## Implementation Integrity Verdict

**Pass, with one qualification.**

The implementation expresses a coherent, product-specific system that could not be lifted onto an
unrelated product. The evidence is unchanged in kind from the baseline and stronger in degree:

- The bundled detector over `src` returns **4 findings, all verified false positives** (below).
- Over the **19 built route HTML files** it returns **747**; **746** are verifiable false positives
  by class, and the **one true-positive class** (25 `low-contrast` findings) is the pager-hover bug
  recorded as P1 below — the detector found statically what axe could not find dynamically.
- Forbidden-property census on the shipped CSS: `.glass-*` **0** (two historical comments in
  `surfaces.css` only), first-party `box-shadow` **0**, `backdrop-filter` **9 declarations, all
  `none`**, non-zero `border-radius` **3, all `--border-radius-full`** on the circular micro-controls
  DESIGN.md:294 sanctions, gradients **4 declarations across the 3 sanctioned data encodings**,
  `rgba(` **0**, `!important` **46, every one inside the four sanctioned cases**
  (`prefers-reduced-motion`, `@media print`, MapLibre/UA overrides, the CV print sheet), `var()` in
  media queries **0**, raw px media queries in source **0**.
- Raw hex outside `variables.css` / `dark.css` / `app.html` exists only in the two derived-token
  modules (`chartColorUtils.ts`, `pdfDesignTokens.ts`) that must hold literals, and every one is
  bound by `designTokenParity.test.ts`. The dark viz ramp's hand-copied hexes still match their
  `dark.css` sources exactly (spot-checked: `umber #965449` ↔ `--sys-viz-7: oklch(0.52 0.09 30)`).

The qualification is the **utility-class layer**. Colour, type and geometry migrated completely
across three design systems — the baseline's headline positive finding — but the _authoring
vocabulary_ did not. `src/styles/utilities/` still ships a Tailwind-shaped sheet of which **22 of 74
classes have zero consumers**, and the markup still carries **5 classes that no stylesheet defines
at all** — `mt-1` (11 uses), `hover:underline` (6), `mb-0`, `py-6`, `md:py-10` — 20 attribute tokens
that style nothing. It concentrates in the CV: **11 of 22 `src/lib/components/cv/*.svelte` are
authored in that vocabulary** (`class="font-medium"`, `class="text-sm mt-1"`,
`class="ml-1 text-primary hover:underline text-sm"`) rather than in the ledger idioms
`ink-signal.css` owns and `/style-guide` documents. That is a real, countable shortcut in one of the
site's two most important pages, and it is why the dimension reads 3 rather than 4. It is **not a
regression** — it predates the baseline, which did not examine class vocabulary — and one sweep
returns the dimension to 4.

- Audit Health Score **17/20 (Good)** — unchanged in total from the post-fix baseline, materially
  changed in composition: Responsive **2 → 3**, Implementation Integrity **4 → 3** (a dimension the
  baseline did not examine, not a regression), Accessibility and Theming hold at 3 and 4 on a far
  larger evidence base.
- Issues: **0 P0, 2 P1, 4 P2, 5 P3** — one of the P3s already fixed in the working tree after the
  build this audit measures.
- The 6.1 batch is real and verified, not asserted: the mobile panel's `min-height`, the 44px facet
  rows, the `RangeSlider` focus ring, `a:hover:not(:where(.btn))`, `.btn-accent:hover` at
  **9.32:1** in midnight, the whole print sheet, both `theme-color` metas, `color-scheme`
  narrowing, and the CV title's 320px break were each re-measured and each holds.
- **The single most important finding is again a chain, not a point defect**, and it is the same
  chain the baseline named: a state the test net does not enter is a state where a WCAG AA failure
  can ship. In 2026-08 it was _dark mode on a page the scan did not visit_. In 2026-09 it is
  **hover** — `axe` evaluates no hover state, so a pager label that resolves to **1.00:1 against its
  own fill** passed 76 clean scans. The 6.1 batch fixed exactly this bug on `.btn-accent`; it fixed
  the instance, and two more instances of the same rule shape survived.

### Top findings

1. **[P1] The pager's current-page label disappears on hover, in both themes.** `.pager-item:hover`
   (`ink-signal.css:1692`) outranks `.pager-item--current` and there is no current-hover rule at
   all, so the label becomes exactly its own ink fill: **1.00:1** daylight (`#191509` on `#191509`)
   and midnight (`#efe7d6` on `#efe7d6`). The shipped variant in `Pagination.svelte` has the same
   shape one notch less severe: **2.82:1** daylight, **1.92:1** midnight, on five index routes.
2. **[P1] The 6.1 "All" chip count broke Label in Name.** Adding the visible count to a button whose
   `aria-label` was written for the label without it leaves an accessible name that does not contain
   the visible text: `aria-label="All types"` against a rendered `All 44`. WCAG 2.2 SC 2.5.3,
   **Level A**, 20 nodes over three routes. The project's axe tag set cannot see it — the rule is
   experimental in axe-core and off by default; Lighthouse catches it, and it is the _only_ audit
   keeping `/publications` from a clean accessibility sheet.
3. **[P2] The two visualisation pages are the sweep blind spot.** Every 6.1 pass — the 44px touch
   floor, the focus-ring rule, the chip idiom — reached the index and record templates and stopped
   at the plate chrome. At 375 under touch emulation: `.toolbar-btn` 36×36, `.viz-zoom-btn` 32×32,
   `.chip.toggle-btn` 38.1, `.search-input` 37.3, `.range-handle` **12×24**, `.breadcrumb-link`
   24.1, `summary.dateline` 32.1. And `NetworkArcDiagram.svelte:501-507` draws keyboard focus as a
   fill-colour change identical to its own hover state — the pattern `ink-signal.css:802-808`
   forbids in so many words, and that 6.1 fixed on `RangeSlider`.
4. **[P2] A foreign authoring vocabulary outlived the system that defined it.** See the Integrity
   verdict above.
5. **[P3] A `var()` that resolves to nothing silently deletes a focus ring.**
   `.close-btn-minimal:focus-visible { outline: none; box-shadow: var(--focus-ring) }` — the
   `outline: none` is valid, the `box-shadow` is not, because `--focus-ring` has never been
   declared. The control on `/cv/timeline` drew no focus indicator at all in the audited build. It
   is the second such token in two audits, both on focus indicators, and neither lint, `check` nor
   axe can see one. Fixed in the tree at 09:33; the missing guard is the finding.

## Detailed Findings by Severity

### [P1] Pager hover destroys the current-page label

- **Location**: `src/styles/components/ink-signal.css:1692` (`.pager-item:hover`), with no
  `.pager-item--current:hover` anywhere; `src/lib/components/molecules/Pagination.svelte:155`
  (`.page-btn:hover:not(:disabled)`) vs `:171` (`.page-btn--current:hover`)
- **Category**: Accessibility / Theming
- **Measured** (1440, transitions disabled, `html` class swapped explicitly):
  - `/style-guide` `.pager-item--current` — rest `color rgb(250,247,239)` on `background
rgb(25,21,9)`; **hover `color rgb(25,21,9)` on `rgb(25,21,9)` → 1.00:1**. Midnight: rest
    `rgb(23,19,16)` on `rgb(239,231,214)`; **hover `rgb(239,231,214)` on `rgb(239,231,214)` →
    1.00:1**.
  - `/publications` `.page-btn--current` — rest 17.02:1; **hover `rgb(30,106,86)` on `rgb(25,21,9)`
    → 2.82:1**. Midnight: rest 15.01:1; **hover `rgb(79,187,153)` on `rgb(239,231,214)` → 1.92:1**.
    Reproduced on `/conference-activity` and `/digital-humanities`; the component also renders on
    `/activities` and `/publications/visualisations`.
- **Impact**: the control that tells a reader where they are in a 44-entry bibliography becomes
  unreadable the moment the pointer rests on it. On the guide's specimen it vanishes entirely.
- **Standard**: WCAG 2.2 SC 1.4.3 Contrast (Minimum), AA
- **Root cause — the rule shape, not the instance**: a family hover rule that restates `color`
  without out-ranking the selected state it sits under. `.pager-item:hover` is `(0,2,0)` against
  `.pager-item--current` `(0,1,0)`; `.page-btn:hover:not(:disabled)` is `(0,3,0)` against
  `.page-btn--current:hover` `(0,2,0)`. `.chip--selected:hover` (`ink-signal.css:721-725`) is the
  one of the three that gets it right — equal specificity, declared later, `background` and `color`
  both restated.
- **Recommendation**: add `.pager-item--current:hover { background: var(--color-primary);
border-color: var(--color-primary); color: var(--color-text-inverted); }` after
  `ink-signal.css:1692`; change `Pagination.svelte:171` to
  `.page-btn--current:hover:not(:disabled)` and restate `background: var(--color-primary)`. Then add
  a hover arm to `designTokenParity.test.ts`'s contrast assertions for all three selected-state
  idioms, since axe structurally cannot cover it.
- **Suggested command**: `/impeccable harden`

### [P1] The "All" chips fail Label in Name

- **Location**: `src/lib/components/entity-index/EntityFilterBar.svelte:75` (`aria-label="All
types"`, visible text at `:80`) and `:106` (`aria-label="All languages"`, visible text at `:111`)
- **Category**: Accessibility
- **Measured**: axe with `label-content-name-mismatch` enabled — **20 nodes** across
  `/publications`, `/conference-activity`, `/activities` × 1440/375 × both themes. Lighthouse
  independently reports it on `/publications` (`<button class="chip chip--selected" aria-label="All
types" aria-pressed="true" data-count="44">`, nodeLabel `ALL 44`; and the `.language-opt` twin).
- **Impact**: a speech-input user who reads `ALL 44` on screen and says "click All 44" does not
  activate the control. It is the reset control of the filter apparatus on three index routes.
- **Standard**: WCAG 2.2 SC 2.5.3 Label in Name, **Level A**
- **Root cause**: the 6.1 batch added the count (`All <span class="chip-count">{…}</span>`) to fix a
  chip that "asserts a count clicking it does not produce" — correctly — but did not revisit the
  `aria-label` written for the label before the count existed.
- **Recommendation**: drop both `aria-label`s and give the rows their context as groups
  (`role="group" aria-label="Type"` on `.chip-row`, `aria-label="Language"` on `.language-row`), so
  each chip's accessible name is its visible text. Then enable `label-content-name-mismatch` in
  `tests-e2e/a11y.spec.ts` — the default `wcag*` tag set does not include it, which is why 76 clean
  axe scans missed it.
- **Suggested command**: `/impeccable harden`

### [P2] Arc-diagram focus is indistinguishable from hover, and is a colour change only

- **Location**: `src/lib/components/visualisations/NetworkArcDiagram.svelte:501-507` vs `:510-512`
- **Category**: Accessibility
- **Measured**: focusing `g.arc-row` (tabindex 0, 40 rows across the two visualisation pages)
  changes exactly one property in the group and its descendants — `text.arc-name` `fill` from
  `rgb(25,21,9)` to `rgb(30,106,86)`. `outline` computes `none` before and after; `:focus-visible`
  sets `outline: none` explicitly at `:502`. The `:hover` rule at `:510-512` sets the identical
  declaration.
- **Impact**: on a pointer-idle page a keyboard user cannot tell focus from a stale hover, and the
  indicator carries no shape. `ink-signal.css:802-808` states the rule in so many words — "A colour
  change alone is not a focus indicator: the ring is the same one every other control on the site
  draws" — and 6.1 applied it to `RangeSlider.svelte:388-393` (verified fixed) while this instance
  stayed.
- **Standard**: SC 2.4.7 Focus Visible is technically met (something changes); SC 1.4.11 Non-text
  Contrast and the project's own rule are not.
- **Recommendation**: mirror `NetworkGraph`'s node, which does this correctly — focusing `g.node`
  takes its `circle` from `stroke rgb(243,238,224) / 1px` to `stroke rgb(30,106,86) / 3px`, a real
  ring on the mark. Keep the pine fill for `:hover`, add a stroke ring for `:focus-visible`.
- **Suggested command**: `/impeccable harden`

### [P2] `.btn-danger` hovers the wrong way in midnight — 2.70:1

- **Location**: `src/styles/components/buttons.css` (`.btn-danger`, `.btn-danger:hover`);
  `--color-danger-dark` is not re-pointed in `src/styles/base/dark.css`
- **Category**: Theming / Accessibility
- **Measured** on `/style-guide`, midnight: rest `color rgb(23,19,16)` on `background

### [P3] `--focus-ring` — a phantom token, fixed in the tree, still documented

- **Location**: `src/styles/CSS-README.md:101` declares it ("Accent-coloured focus indicator").

- **Category**: Implementation Integrity / Accessibility

  (`outline: var(--border-width-medium) solid var(--color-border-focus)`), written 09:33 — five

## Patterns & Systemic Issues

1. **Selected-state hover is the system's structural blind spot.** Three families quote the same
   idiom — solid ink fill, inverted label. `.chip--selected:hover` restates both properties at equal
   specificity and is correct. `.pager-item--current` has no hover rule at all. `.page-btn--current:hover`
   exists but ranks below its family's hover. Two of three are broken, at 1.00:1 and 1.92:1, and
   **no automated check in the project can see any of them**, because axe evaluates no hover state.
   The 6.1 batch fixed this exact rule shape on `.btn-accent` and wrote the lesson into DESIGN.md:313
   — as an instance, not as a class.
2. **Verification scoped narrower than the design contract — again, one level down.** The baseline's
   finding was dark mode scanned on one page of eleven. The fix generalised the _pages_. What
   remains unscanned are _states_: hover (two AA failures), and accessible-name rules that are
   experimental in axe and therefore outside the project's tag set (one Level A failure). Both
   classes are cheap to add to `a11y.spec.ts`.
3. **A fix that adds visible text can break the accessible name.** The 6.1 count fix was correct on
   its own terms and created a 2.5.3 failure on the same button. Any change to a control's visible
   label needs its `aria-label` re-read in the same edit.
4. **The visualisation pages are downstream of every sweep.** Touch floors, focus rings, chip
   idioms, breadcrumb targets — each 6.1 pass reached the index and record templates and stopped at
   the plate chrome. The route list every critique works from should carry both visualisation pages
   as first-class templates, not as a trailing check.
5. **A foreign authoring vocabulary outlived its system.** Colour, type and geometry migrated across
   three design systems with zero survivors; the utility-class layer never did, and it still carries
   five classes that style nothing.
6. **An undeclared custom property fails silently, and twice it has failed on a focus ring.**
   `--color-focus` in `LocationMap.svelte` (found by the `design-philosophy-auditor` baseline, fixed
   in 6.1) and `--focus-ring` in `TimelineDetailCard.svelte` (in the audited build, fixed in the
   tree at 09:33) both made a keyboard indicator disappear, and both passed lint, `svelte-check`,
   the unit suite and 76 axe scans. `CSS-README.md:101` still documents the second one, joining the
   baseline's "the only gradient" and "h4–h6 serif" as docs falsifiable by grep. The remedy is
   mechanical: assert that every `var(--x)` in `src/` names a declared property.

## Method notes

- **Instruments, not opinions.** Every number above was read off the served production build at
  `http://localhost:4174` with transitions disabled (`* { transition: none !important }`) and the
  `html` theme class set explicitly before any computed-style read, because the body carries a
  300 ms background transition. Probe scripts live in the session scratch directory only.
- **Coverage.** 19 routes (`/`, `/publications`, two publication records, `/publications/
visualisations`, `/conference-activity`, `/conference-activity/slides`, `/conference-activity/
visualisations`, `/communications/archives-algorithms-iwac-2025`, `/activities`,
  `/activities/amira-launch-2026`, `/research`, `/research/religious-activism-campuses-togo-benin`,
  `/digital-humanities`, `/cv`, `/cv/timeline`, `/teaching`, `/style-guide`, `/404.html`) × 1440 and
  375 × daylight and midnight for axe (76 scans) and focus; × 320/375/640/720/768/1024/1440 for
  overflow (133 loads); 375 with touch emulation for the target census; 1440 both themes for the
  hover sweep.
- **The hover sweep** hovered every visible `a`, `button`, `summary` and `[role="button"]`
  ungrouped on five representative routes and one representative per class signature on five more,
  computing the effective background by walking ancestors and compositing alpha. **Two probe
  artefacts were identified and discarded**: Chrome serialises `color-mix()` backgrounds as
  `color(srgb …)`, which the compositor could not parse, so `.btn-accent:hover` in midnight appeared
  as 1.00:1 — direct measurement gives `rgb(23,19,16)` on `color(srgb 0.467 0.776 0.660)` =
  **9.32:1**, and the 6.1 fix is sound. Every reported failure was re-verified by reading the
  element's own computed `backgroundColor` and `color` before and after a real pointer hover.
- **The 200% zoom test was redone.** Setting `documentElement.style.zoom = 2` scales content and
  doubles `scrollWidth`, reporting an overflow on all 19 routes that does not exist. The correct
  emulation — halving the viewport to 720 CSS px — reports **0 overflow**, and 640 px is clean too.
- **Two further probe errors were caught and their findings withdrawn**, both by cross-checking the
  probe against the shipped CSS rather than trusting it:
  - _Print._ Reading `getComputedStyle(el).display` on `.theme-toggle` returns `inline-flex` under
    print emulation, which looks like a control printing on paper. Its parent `.desktop-controls`
    is `display: none` (`Header.svelte:347-349`, present in the build), so the toggle renders a
    0×0 box and prints nothing. **Measure effective visibility by walking ancestors, not the
    element's own `display`.**
  - _`::selection`._ Walking `document.styleSheets` and testing `selectorText` returned zero
    `::selection` rules, which looked like an unowned colour surface. `grep` over
    `build/app/immutable/assets/0.CRtJL-K6.css` finds the rule, and `typography.css:28` declares it.
    **A CSSOM walk is not a substitute for reading the shipped stylesheet.**
- **The working tree moved under the frozen build.** The build this audit measures was written at
  09:28 and was not rebuilt; the 6.1 fixes were still uncommitted in the tree, and files continued
  to be written while the audit ran (09:33, 09:36). Every source line cited above was re-read
  against the tree at the end of the run and re-verified; the one finding this changed is
  `--focus-ring`, fixed at 09:33 and recorded as such rather than silently dropped. `git status`
  is not a reliable freshness signal here: `HEAD` is pre-6.1, so a clean-looking diff against it
  would have been the wrong baseline entirely.
- **Two accessibility rule classes sit outside the project's tag set.** `label-content-name-mismatch`
  (SC 2.5.3) is experimental in axe-core and disabled by default; enabling it surfaced the P1 above.
  `p-as-heading` fires on `Footer.svelte:14` — `<p class="footer-wordmark" id="footer-brand-heading">`
  naming a `<section>` via `aria-labelledby` — on all 18 routes. **Recorded as a false positive**:
  the wordmark is a nameplate, not a section heading, and promoting it to `<h2>` would inject
  "Frédérick Madore" into every page's heading outline.
- **The two search fields do not draw the global ring, and that is deliberate.**
  `entity-index.css:140` sets `.pub-search-input:focus { outline: none }`, and the indicator moves
  to the wrapper: `.pub-search:focus-within { border-color: var(--color-accent) }`
  (`entity-index.css:108`), mirrored by `.facet-combobox-field:focus-within`
  (`ink-signal.css:1518`, with the rationale written at `:1550` and a specimen on `/style-guide`
  at `:1460`). Measured pine-on-surface at ≈4.9:1, above the 3:1 SC 1.4.11 asks of a state
  indicator. **Not a finding** — but it is the weakest indicator on the site, and worth re-reading
  whenever the ring rule is revisited.
- **Contrast figures** were computed from the elements' own composited colours in the rendered page,
  so they are exact for the pairing as it ships, not for the token pairing in the abstract.
- **The bundled detector's URL engine is degraded on this machine** (`puppeteer is required for URL
