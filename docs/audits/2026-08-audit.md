## Implementation Integrity Verdict

**Pass.** The implementation expresses a coherent, product-specific system that could not be
swapped onto an unrelated product. Evidence: the mechanical detector returns a single finding
across all of `src/` (see below, a false positive); the design-philosophy audit found **zero**
retired palette colours, **zero** retired fonts, **zero** live `box-shadow` or `backdrop-filter`,
and **zero** `rgba()` in stylesheets across three previous design systems' worth of migration —
including in the ECharts, MapLibre and jsPDF layers, where token discipline usually erodes first.

The one detector finding is `cream-palette` ("a warm cream page background has become the default
tasteful AI surface"). This is a **false positive against a pinned brief**: warm paper `#faf7ef`
is the deliberate, documented ground of Ink + Signal, chosen as the press-archive paper stock, not
reached for by reflex. Suppressed via `detector.ignoreRules` rather than changed.

### Top findings

1. **[P1, fixed] Accent button fails WCAG AA in midnight.** `.btn-accent` set its label to raw
   `--sys-color-paper`, which does not flip with the theme. The accent brightens to pine
   `#4fbb99` at midnight, so paper-white text rendered at **2.20:1** — well under the 4.5:1
   minimum. This is the "Access publication" CTA on every publication detail page (the citation
   path, the site's primary job) and the action on the 404 page. Fixed by using the semantic
   `--color-text-inverted`: 6.03:1 in daylight, 7.83:1 at midnight.
2. **[P1, fixed] The test net could not see it.** `a11y.spec.ts` scanned the `wcag2a/2aa/21a/21aa`
   tag set — not `wcag22aa`, though PRODUCT.md now commits to WCAG 2.2 AA — and scanned dark mode
   on the home page **only**, where the accent button does not appear. Its own doc comment claimed
   a "content detail page" was covered; none was. Fixed: added `wcag22aa`, added a publication
   detail page, and expanded dark-mode scanning to three pages. All 8 scans pass.
3. **[P1, fixed] The downloadable CV shipped a failing contrast ratio.** `pdfDesignTokens.ts` and
   `chartColorUtils.ts` hand-copy hex values from `variables.css`. When `--sys-color-ink-faint` was
   darkened to `#6b634e` to honour an explicit "≥4.5:1 on all paper surfaces" comment, both copies
   kept the old `#93896f` — **3.24:1 on warm paper, 3.00:1 on the surface step**. The PDF value is
   unconditional, so every generated CV carried it on every label. Fixed, and bound by a new
   regression test.

## Detailed Findings

### [P1] Accent button contrast in midnight — FIXED

- **Location**: `src/styles/components/buttons.css` (`.btn-accent`, `.btn-outline-accent:hover`,
  `.btn-danger`), `src/lib/components/common/Footer.svelte` (`.scroll-to-top:hover`)
- **Category**: Accessibility / Theming
- **Impact**: The primary action on the citation path was effectively illegible for dark-theme
  users. 2.20:1 against a 4.5:1 requirement.
- **Standard**: WCAG 2.2 SC 1.4.3 Contrast (Minimum), AA
- **Root cause**: A raw `--sys-color-*` foundation token used as a text colour against a
  background that _does_ flip with the theme. The class of bug, not the instance, is the lesson.
- **Fix applied**: `color: var(--color-text-inverted)` in all four places.
- **Residual**: `.btn-danger` at midnight computes 4.46:1 — marginally under AA. It is currently
  **unused** (no destructive actions exist on the site), so this is latent. Resolve by nudging
  `--sys-color-danger-bright` lighter before the variant is ever used. Tracked as P3 below.

### [P1] Accessibility test coverage gap — FIXED

- **Location**: `tests-e2e/a11y.spec.ts`
- **Category**: Accessibility
- **Impact**: The suite asserted conformance to a standard the project no longer targets, and its
  dark-mode assurance covered one page of eleven page families.
- **Fix applied**: `wcag22aa` added to the tag set (this is what enforces SC 2.5.8 Target Size and
  SC 2.4.11 Focus Not Obscured); publication detail page added; dark-mode scans extended to home,
  publications index, and publication detail. 8 scans, all passing.

### [P1] Derived token drift — FIXED

- **Location**: `src/lib/utils/chartColorUtils.ts:289`, `src/lib/utils/pdfDesignTokens.ts:89`
- **Category**: Theming / Accessibility
- **Impact**: 3.24:1 label text in the generated CV and in chart fallbacks.
- **Structural cause**: Two modules must hold literal copies of the palette — jsPDF needs RGB
  triples with no document to read computed styles from, and ECharts/MapLibre cannot parse
  `color-mix()` or `oklch()`. Both duplicates were legitimate; **neither was bound to the source**.
- **Fix applied**: values corrected, plus a new guard at
  `src/lib/utils/designTokenParity.test.ts` that parses `variables.css`, resolves `var()` chains,
  and asserts every derived constant still matches the token it names. It also asserts the
  palette's stated contrast promises directly, including the accent-button pairing in both themes.
  Verified to fail when the stale value is reintroduced.

### [P2] Dead glass-era fallback with a live rendering side effect — FIXED

- **Location**: `src/lib/components/menu/DropdownMenu.svelte:71-75`
- **Category**: Implementation Integrity
- **Impact**: An `@supports not (backdrop-filter)` block guarded a feature the system removed, but
  was not inert: browsers without `backdrop-filter` got `--color-background` while everyone else
  got `--color-surface-elevated` — a gratuitous rendering difference.
- **Fix applied**: block deleted.

### [P2] Documentation falsifiable by grep — FIXED

- **Location**: `src/styles/CSS-README.md`, and the `DESIGN.md` written earlier this session
- **Category**: Implementation Integrity
- **Impact**: Both claimed `.hbar` was "the **only** gradient in the system". Two others exist:
  the `VolumeControl` track (same hard-stop technique, inline) and the `NetworkMatrix` density
  legend (a genuinely continuous ramp). Both encode real data, so both are legitimate under
  "data is the only ornament" — but a rule contradicted by the code teaches future work to
  ignore the rule.
- **Fix applied**: all three named as sanctioned data-encoding exceptions in `CSS-README.md`,
  `DESIGN.md`, the sidecar, and the auditor agent.

### [P2] Voice-casting conflict at `h6` — RESOLVED AS DOCUMENTATION

- **Location**: `src/styles/base/typography.css:132-140` vs `.impeccable.md` / `CLAUDE.md`
- **Category**: Implementation Integrity
- **Detail**: `h6` is cast in the mono data voice (uppercase, letterspaced) with an explicit
  comment saying so, while the brief cast `h4`–`h6` as serif. `CSS-README.md` already said
  `h4`–`h5`, so the docs disagreed with each other as well.
- **Resolution**: the code is deliberate and defensible — the smallest heading tier in this system
  _is_ a metadata label — so the **documentation was corrected to match**, not the code.
  `DESIGN.md`, `CLAUDE.md` and the sidecar now record `h6` as the one heading element in the data
  voice, stated as an intentional exception to the Two Voices Rule.

### [P2] Cool fallback on the map surface — FIXED

- **Location**: `src/lib/components/visualisations/MapVisualization.svelte:149`
- **Impact**: `colors.surface || '#ffffff'` — wrong temperature in daylight and badly wrong on the
  microfilm ground. Defensive path only, so low likelihood.
- **Fix applied**: falls back to the warm surface `#f3eee0`.

### [P3] Circular micro-controls bypass the radius token — FIXED

- **Location**: `CareerTimeline.svelte:452`, `timeline/TimelineTooltip.svelte:68`
- **Detail**: hardcoded `border-radius: 50%` where `--border-radius-full` exists for exactly this
  sanctioned case. Token hygiene, not a philosophy breach. Both now use the token.

### [P3] Orphan value in the PDF token file — DOCUMENTED, NOT CHANGED

- **Location**: `src/lib/utils/pdfDesignTokens.ts:87` — `TEXT: [58, 53, 42]` (`#3a352a`)

## Patterns & Systemic Issues

1. **Hand-copied token duplicates drift silently.** Two modules must hold literal palette copies
   for legitimate technical reasons, and both fell behind. Now bound by a parity test — the
   pattern to remember is that any _necessary_ duplicate needs a binding test at the moment it is
   created.
2. **Raw foundation tokens (`--sys-color-*`) used where semantic tokens belong.** Four instances,
   all producing theme-dependent bugs invisible in daylight. Foundation tokens do not flip; only
   semantic ones do. Worth a lint rule.
3. **Verification scoped narrower than the design contract.** Dark mode is a first-class designed
   pass in the brief but was scanned on one page; the conformance target had moved to WCAG 2.2
   while the tests still asserted 2.1. Both now aligned.
4. **Documentation asserting absolutes that the code contradicts** ("the only gradient",
   "h4–h6 serif"). Three separate docs disagreed. When a rule has exceptions, naming them keeps
   the rule enforceable.

## Positive Findings

Genuinely strong, and worth protecting:

- **Migration discipline is exceptional.** Three design systems' worth of retired palettes
  (blue/teal, terracotta/gold, ink-blue/amber/vermillion) with **zero** surviving hexes, and zero
  retired font references. The `.glass-*` → `.surface-*` rename is fully complete, with only
  historical explanatory comments left.
- **Token discipline extends into the hard layers.** ECharts, MapLibre and jsPDF are where design
  systems normally break down; here they carry correct Ink + Signal values throughout.
- **`!important` is fully confined** to its sanctioned cases (reduced-motion, print, MapLibre
  z-index overrides). No `var()` in media queries anywhere. No live shadows, glass, or glow.
- **Performance budgets pass with real headroom**: shared entry JS 102.8 KiB / 140 KiB, heaviest
  route 710.7 KiB / 850 KiB, no heavy library statically reachable, 229 image variants current,
  and all 196 sitemap URLs resolve to a prerendered page.
- **Accessibility infrastructure was already in place** — axe-core wired into the E2E suite, chip
  padding explicitly sized to clear SC 2.5.8, focus-visible rings on every control, reduced-motion
  and high-contrast blocks. The gap was coverage breadth, not intent.

## Method notes

- The bundled detector initially ran **degraded** ("HTML parser modules unavailable… findings are
  an undercount, not a clean bill of health") and reported zero findings. Its parser dependencies
  (`htmlparser2`, `css-select`, `css-tree`, `domutils`) were installed into the plugin's own skill
  directory so custom properties, selector matching and computed contrast were actually evaluated.
  **A future run should confirm the detector is not degraded before trusting a clean result** —
  note that a plugin update will wipe those modules.
- Contrast figures were computed directly from the token values rather than sampled from a
  rendered page, so they are exact for the specified pairings.
- The `design-philosophy-auditor` agent corrected three stale premises in its own brief during the
  run (the referenced audit script no longer exists; `.glass-*` is fully migrated; the PDF
  generator has moved to `pdfCvGenerator.ts` + `pdfDesignTokens.ts`). The agent file has been
  updated so its next run starts from accurate ground truth.
